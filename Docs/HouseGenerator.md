# Генератор домов 2.0 — дизайн

Цель: дома, где комнаты сильно отличаются друг от друга — любой длины и формы, прямоугольные, угловатые, скруглённые,
в один и в два-три этажа, — и при этом остаются хорошими уровнями для стелса: петли обхода, укрытия, тёмные углы,
опасные открытые залы, вертикальные линии обзора. Всё по-прежнему детерминировано от сида и строится из префабов.

## 1. Что не так сейчас

Дом — сетка клеток 10 × 10 м. Комната = клетка (или несколько клеток без стены между ними). На этой сетке держатся
стены и двери (`EdgesX/EdgesZ`), мебель по четвертям клетки (`Quadrants`), лестница в углу клетки, свет и тьма по клеткам,
карта (`MapSketch`), архитектурный декор (`ArchitecturePlanner`), датчики, автопилоты и тесты (~25 файлов).
Поэтому разнообразие упирается не в генератор, а в модель данных: её и меняем первой.

## 2. Модель данных: план этажа из многоугольников

```
HousePlan
  Footprint[floor]          контур здания на этаже (не обязательно прямоугольник: Г, П, с внутренним двором, уступы)
  Rooms                     Room: Id, Type, Floor, Levels (1..3 этажа в высоту), Outline (многоугольник), Tags
  Walls                     WallSeg: A, B (отрезок, может быть диагональным), Floor, Height, RoomLeft/RoomRight (−1 = улица)
  Openings                  на отрезке стены: Door / Open / Vent / Squeeze / Window, позиция t и ширина
  Voids                     дыры в перекрытиях: атриумы, лестничные проёмы (+ перила по краю)
  Stairs                    лестница: тип (угловая П-образная, прямой марш, открытая в атриуме), этажи, место
  Raster[floor]             растр 0,5 м: Id комнаты в каждой клетке — быстрые запросы «где я», свободный пол, тьма
```

- **Контур комнаты** — ортогональный многоугольник на шаге 0,5 м плюс «обработка углов»: срез 45°, скругление дугой
  (дуга = ломаная из отрезков по ~0,8 м), и особые формы целиком: круг/восьмиугольник (ротонда), трапеция.
- **Стены выводятся из контуров**, а не задаются: общая граница двух комнат = одна стена, граница с улицей = наружная.
  Сливаем коллинеарные куски, на стыках — колонны (как сейчас посты в углах).
- **Растр — источник правды для запросов** (`RoomAt(point)`, свободно ли место под мебель, тёмная ли точка, какой
  участок открыла карта), многоугольники — для геометрии. Старые API (`RoomCenterAt`, `IsDarkAt`, `Neighbours`)
  остаются, но работают по комнатам, а не по клеткам — потребители меняются минимально.

## 3. Конвейер генерации (сверху вниз, как работает архитектор)

1. **Программа дома.** Тип дома (`HouseKind`, уже заложен в маршруте: сейчас только Office) задаёт список помещений:
   сколько, каких площадей, кто с кем рядом (кухня у лаунжа, переговорные у холла, серверная в глубине, туалеты у
   коридора), глубина приватности (лобби у входа → открытые офисы → кабинеты → серверная/хранилище с лутом).
2. **Масса здания.** Контур первого этажа (прямоугольник, Г, П, двор, «гантель») и этажи выше (уступы, терраса на
   крыше нижнего). Растёт с домом, как сейчас.
3. **Зонирование.** Разрезаем контур на участки под программу: рекурсивное деление (BSP) со взвешенными площадями,
   потом **коридоры-хребты** (общая зона) — прямые, с изломом, кольцевые; помещения нанизываются на хребет.
   Соседние участки сливаются в Г/Т/П, часть залов — сквозные, без коридора («open space»).
4. **Форма.** Каждой комнате — грамматика формы по типу: углы срезать/скруглить, ниша, эркер, колонны в большом
   зале, ротонда вместо прямоугольника. Плюс **сет-пьесы** — заготовки-виньетки (круглый холл с ресепшеном, стеклянная
   переговорная, серверный зал с фальшполом, кабинет директора с сейфом), вставляемые по программе: запоминающиеся места.
5. **Вертикаль.** Атриумы (дыра через 2–3 этажа с галереями и перилами), залы двойной высоты (склад, лобби, серверная),
   антресоли, открытые лестницы внутри атриума, лестничные клетки. Атриум = вертикальная линия обзора и звука.
6. **Связность.** Граф дверей на смежностях: остов (всё достижимо) + петли (стелсу нужны обходы) + потайные пути
   (лазы, щели) как альтернативы; ограничиваем тупики и длину пути до лута. Считаем метрики графа и проверяем тестом.
7. **Наполнение.** Мебель — грамматика раскладки по многоугольнику, а не по четвертям: «вдоль стены» (полосы у стен в
   обход дверей и окон), «острова» в центре (кластеры столов, стол переговорной), «проходы» (держим 1,2 м от дверей),
   колонны и ниши как места для укрытия. Работает на растре свободного пола — годится для любой формы.
8. **Охрана, свет, лут.** Патрули по петлям коридоров, камеры на углах с хорошим обзором (считаем по растру), лазеры в
   проёмах, тьма и мерцание по комнатам, лут — по глубине приватности.

Каждый шаг — чистый C# со своим потоком рандома (`RandomChannel`), как сейчас; от сида дома — один и тот же дом на всех пирах.

## 4. Как это строится в Unity (правило «только префабы» сохраняется)

- Стены: прямой отрезок — растянутый куб-блок (как сейчас), диагональ — тот же блок, повёрнутый; дуга — цепочка коротких
  блоков с постами на стыках. Проёмы режут отрезок (косяки, перемычка), двери встают в проём любого направления.
- Полы и перекрытия: многоугольник этажа минус пустоты → растр 0,5 м → максимальные прямоугольники → растянутые плиты;
  кромка под стенами, так что ступенек не видно. Атриум — дыра + перила по кромке (префаб перил).
- Навмеш печётся в рантайме — ему форма безразлична. Зона `Stairs` для лестниц сохраняется.
- Окна — на наружных отрезках, где хватает длины; на дугах — нет.
- Декор стилей (`ArchitecturePlanner`) уже работает по «граням стен» — учим его диагоналям и дугам (плинтусы гнутся
  цепочкой, панели — только на прямых).
- `MeshBatcher` склеивает по комнате, а не по клетке.

## 5. Геймплей стелса, который надо пересчитать

- **Восприятие через этажи:** сейчас «тот же этаж» — по индексу этажа. В атриуме робот на галерее должен видеть и слышать
  низ, а перекрытие глушит звук только там, где оно есть: `Perception` спрашивает у плана, есть ли плита между точками.
- **Карта:** `MapSketch` рисует отрезки и многоугольники (диагонали и дуги), атриум виден на обоих этажах.
- **Темнота и свет** — по комнате; в большом зале несколько светильников по раскладке, часть может не гореть —
  тёмные острова внутри зала.
- **Узкие места:** длинный коридор = опасная прямая линия обзора; генератор обязан давать ниши/колонны/повороты в
  коридорах длиннее ~15 м.

## 6. Инструмент: план дома картинкой без запуска игры

`Tools/dev.sh plans` (EditMode-тест или батч-метод) пишет SVG планы этажей для 20 сидов: комнаты разными цветами,
двери, лазы, лестницы, атриумы, мебель, патрули, камеры, метрики (петли, тупики, глубина). Итерации над генератором
идут за секунды, а «критик по картинкам» (как для моделей) оценивает разнообразие и читаемость. Это первое, что пишем.

## 7. Проверки (тесты)

Детерминизм; всё достижимо (граф и навмеш); стены не пересекаются и не перекрываются; дверь ≥ ширины проёма + косяки;
мебель не пересекает стены, двери, лестницы и друг друга; перила по всей кромке пустот; метрики разнообразия на 100 сидах
(доли форм комнат, разброс площадей, число атриумов, петли/тупики в коридорах); бюджет числа стен и плит (производительность).

## 8. Этапы

| # | Что | Видно в игре |
| --- | --- | --- |
| 0 | Модель `HousePlan` + перенос текущего генератора в неё без изменений + SVG-планы + адаптеры старых API | ничего не меняется (проверка, что основа держит) |
| 1 | Новый конвейер: программа, масса здания (Г/П/двор), зонирование BSP, коридоры, прямоугольные и Г/Т/П комнаты любого размера, граф дверей с петлями, мебель по грамматике | комнаты любой длины и формы, коридоры, дома разной формы |
| 2 | Углы и особые формы: срезы 45°, скругления, ротонды, восьмиугольники, колонны, ниши, сет-пьесы | угловатые и скруглённые комнаты |
| 3 | Вертикаль: атриумы, залы в 2–3 этажа, галереи, открытые лестницы; восприятие и карта через пустоты | комнаты в несколько этажей |
| 4 | Типы домов (офис, банк, лаборатория, отель…), баланс, метрики разнообразия, автопилоты | дома разного характера |

### Что сделано (2026-11-12)

Все этапы 0–4 есть в коде: `HousePlan` (растр 0,5 м, стены из границ + наклонные/дуговые сегменты, проёмы на стенах, перила галерей),
`PlanGenerator` (масса бар/Г/Т/П/двор/Н + пристройка, лобби у фасада, лестничные холлы, коридоры, BSP по классам размеров, Г/Т-слияния,
срезы и скругления углов с «карманами», ротонды и восьмиугольники, атриумы в 2–3 этажа с галереями, связность Краскалом + петли, лазы, щели),
`Furnisher` (мебель на любой форме комнаты, проходы 1,25 м, `EnsureWalkable` убирает мебель-барьеры), `HouseKinds` (офис, бизнес-центр,
дата-центр, склад, штаб-квартира — меняют программу комнат и формы). `LevelGenerator` — «сгенерируй и проверь»: до 16 вариантов плана, берётся
первый, где до каждой комнаты можно дойти. Картинки планов — `Tools/dev.sh plans`.

Не сделано: колонны, ниши и сет-пьесы; уступы этажей (верхний этаж меньше нижнего); открытые лестницы в атриуме; срезы углов, пожалуй, часты;
генерация ≈ 0,6 с на большой дом.

## 9. Открытые решения

- Типы домов кроме офиса — делать ли (этап 4) и какие.
- Насколько «реальной» архитектуры хотим против «игровой» (лабиринтность, тайные ходы).
- Размер дома в метрах сейчас растёт сеткой 10 м; новый генератор позволяет плавный рост — как связать с квотой и командой.
