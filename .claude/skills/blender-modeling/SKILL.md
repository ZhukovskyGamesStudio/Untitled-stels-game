# Как моделировать (Blender из Python)

Модель — это не код, а картинка. Код пишется вслепую, поэтому **каждая итерация заканчивается просмотром**:
лист рендеров + проверка меша. Без просмотра модель не готова.

Blender 5.2: `D:/Apps/Steam/steamapps/common/Blender/blender.exe` (не в PATH). Запуск:
`-b --factory-startup --python-exit-code 1 --python <скрипт> -- <аргументы>` (без `--python-exit-code 1` упавший скрипт
возвращает 0).

## Инструменты

| Файл | Что делает |
| --- | --- |
| `Tools/Blender/shapes.py` | словарь форм: всё возвращает bmesh в мировых координатах; `part()` склеивает в объект-роль и отделывает |
| `Tools/Blender/review.py` | лист рендеров (8 фиксированных ракурсов + крупные планы + ряд шейдинга) и проверка меша с воротами |
| `Tools/Blender/vendor/scenario/` | `bx_audit.py`, `bx_review.py` из scenario-labs/skills (MIT, без правок): ворота `deliverable` зовёт `review.py` |
| `Tools/Blender/guard_mk2.py` | пример модели целиком на `shapes.py` (охранник, контракт частей игры) |
| `Tools/Blender/meshfix.py` | починка при экспорте (`fix_objects`, её зовут `export` всех скриптов моделей): притянуть висящие куски, развести совпадающие грани, убрать двойные стенки и мусор, вывернутое — наружу |
| `Tools/Blender/audit_models.py` | пакетная проверка папок FBX: таблица Markdown, худшие сверху, сообщения ворот |

```bash
B="D:/Apps/Steam/steamapps/common/Blender/blender.exe"
"$B" -b --factory-startup --python-exit-code 1 --python Tools/Blender/guard_mk2.py -- <scratchpad>/guard.fbx
"$B" -b --factory-startup --python-exit-code 1 --python Tools/Blender/review.py -- <scratchpad>/sheet.png <старая.fbx> <новая.fbx> --focus 0,-0.05,1.6,0.45
"$B" -b --factory-startup --python-exit-code 1 --python Tools/Blender/review.py -- <scratchpad>/final.png <новая.fbx> --shading
```
Лист: блок 4×2 на модель (модели сверху вниз в порядке аргументов): спереди · 3/4 · сбоку · сзади / сверху · 3/4 сзади ·
сетка · **миниатюра 64 px** (что читается через комнату). `--focus x,y,z,r` — ряд крупных планов вокруг точки. Рендер — Workbench,
~3 с на модель. Цвета ролей: Body серый, Accent оранжевый, Eye голубой, прочие имена — сиреневые (значит, игра покрасит их как Body).
`--shading` — ещё ряд: глина-матcap (формы без цвета) · матcap проверки нормалей (резкий перелив = сломанное затенение) ·
**задние грани отсечены на пурпурном фоне** (как рисует Unity: пурпурное пятно на модели = дыра в игре) · вид снизу.

Проверка (`CHECK …`) печатает треугольники по частям, размер и пол, дыры (open edges), вырожденные грани и **DETACHED** —
куски, не касающиеся остальной модели (> 4 мм). Висящие детали — главный дефект сгенерированных моделей, глаз их не видит.
Каждый DETACHED — либо исправить, либо осознанно принять (отдельные предметы в галерее).

**GATE** — ворота scenario-labs (`bx_audit.deliverable`, профиль `game`): висящие и спрятанные внутрь детали, **z-fighting**
(две грани в одной плоскости — мерцают в игре), вывернутые детали, грани внутрь (Unity их не рисует), дубли граней, масштаб, UV.
`GATE ERROR` — чинить до того, как модель пойдёт в игру. Ожидаемые предупреждения нашего конвейера: `n-gons` (крышки лофтов;
Unity триангулирует сам) и `no material` (материалы по ролям назначает `AssetBuilder`). Найти, где именно дефект, —
сравнить центры граней, как в `bx_audit.deliverable` (цикл `find_nearest_range`), и напечатать координаты.

### Много моделей сразу

```bash
"$B" -b --factory-startup --python-exit-code 1 --python Tools/Blender/audit_models.py -- <scratchpad>/audit.md Assets/_Game/Art/Models/Styles/Lofi --json <scratchpad>/audit.json
"$B" -b --factory-startup --python-exit-code 1 --python Tools/Blender/review.py -- <scratchpad>/lineup.png Assets/_Game/Art/Models/Styles/Guards/*.fbx --lineup 4 --no-check
```
`audit_models` — 70 моделей за секунды; мебель, предметы и уровень проверяются с полом как опорой (`review.check floor=True`),
роботы и персонажи — без (колесо, касающееся пола, но не корпуса, — дефект). `--loose` — набор отдельных деталей (StyleKit).
`--lineup N` — линейка: у каждой модели вид спереди и 3/4, N моделей в ряд, порядок в `<лист>_legend.txt`; так критик
сравнивает стили между собой. Перед тем как писать в `Assets`, генерируй в scratchpad (скрипты принимают корень вывода
первым аргументом) и сравнивай таблицы «до/после».

## Цикл

1. **Задача и контракт.** Габариты, где перед (−Y в Blender = +Z в Unity), какие части нужны игре (имена-роли:
   `Body*` / `Accent*` / `Eye*`, у ног — `AccentLeg0/1` с разрезом по колену `split_at`), бюджет треугольников.
2. **Крупные формы (силуэт).** Сначала 5–8 больших лофтов/скруглённых коробок, без деталей. Лист → силуэт и пропорции
   должны читаться на миниатюре. Если не читаются — детали не спасут.
3. **Средние формы.** Суставы, пластины, швы (`groove`), разделение панелей, ступни, кисти.
4. **Мелочь** — только там, куда смотрит глаз: голова, лицо/объектив, кисти, перед корпуса. Пустые плоскости — отдых, а не недоделка.
5. **Проверка**: `review.py` + `--focus` на главную деталь. Ноль DETACHED, `GATE PASS`, бюджет соблюдён; в финале — `--shading`.
6. **Независимый критик**: субагент получает только PNG и описание (без кода и без моих намерений), отвечает: вердикт
   «было/стало», читаемость на 64 px, пропорции, дефекты, **топ-6 правок по влиянию**. Шаблон — ниже. Применить 2–4 главные правки,
   повторить 5–6. Обычно хватает 2–3 кругов.
7. Сравнивать **попарно** (старая и новая на одном листе), а не «в целом хорошо ли».

## Словарь форм (`shapes.py`)

| Нужна | Функция | Пример |
| --- | --- | --- |
| корпус, ящик, плита | `rbox(size, loc, r, seg, taper, rot, vertical_only)` | `rbox((.4,.17,.4), (0,.25,1.38), r=.045, seg=3, taper=(.92,.95))` |
| торс, голова, конечность, сиденье, бутылка | `loft([(z, a, b, n, x, y), …], seg, round_caps, axis)` — сечения-суперэллипсы | `n` 2 = эллипс, 3–4 скруглённый прямоугольник, 8 = почти коробка; `a == 0` — полюс |
| объектив, ручка, лампа, сустав, колесо | `lathe([(r, z), …], seg, axis, loc)` | ребристая шея — чередовать радиусы |
| кабель, шланг, труба, поручень | `tube(points, radius, res, smooth, radii)` | Безье через точки |
| шов панели | `groove(bm, axis, value, width, depth)` | шов вокруг формы на высоте `value` |
| утопленная панель | `inset_faces(bm, facing((0,-1,0), min_area), thickness, depth)` | |
| вырез, отверстие, прорезь | `boolean(bm, cutter, "DIFFERENCE")` + `bevel_edges(bm, r)` | фаска после выреза обязательна |
| мягкая органика из грубой клетки | `smooth(bm, levels, crease_angle)` | клетка из `rbox(r=0)` / низкого `loft` |
| щупальце, шланг, стебель, мультяшная рука | `skin(points, radii, edges)` | скелет + радиусы |
| вентиляция, болты | `grille(center, w, h, n, axis)`, `bolts(points, r, depth, axis)` | только на плоских участках |
| симметрия, сужение | `mirror_x(bm)`, `taper(bm, axis, k0, k1)` | строить левую половину, зеркалить |

`part(name, [bm…])` склеивает и отделывает: гладкое затенение, острые рёбра > 35°, Weighted Normal (плоское остаётся плоским,
фаска ловит блик), UV кубом в метрах. `export_fbx(path, objs)` — ориентация игры, модификаторы применены.

## Правила формы

- **Ни одного острого 90° ребра на виду.** Фаска 1–3 % размера детали, у крупных ≥ 1 см; маленьким — `seg=1–2`, крупным `seg=3`.
- **Форма лофтится, а не складывается.** Торс — один лофт с меняющимися сечениями (грудь шире пояса, наклон вперёд), а не три коробки.
- **Большое / среднее / мелкое ≈ 70 / 20 / 10.** Сначала большие массы, потом стыки, потом мелочь.
- **Каждая деталь касается соседей или входит в них.** Сустав (шар/цилиндр) прячет стык двух частей.
- **Читаемость на 64 px**: силуэт головы, плеч, ног и главный светящийся элемент должны угадываться на миниатюре.
- **Детали — на плоских участках.** Над скруглением болт/решётка повисают (DETACHED).
- **Детали входят друг в друга на 1–3 см, а не касаются.** Стык «грань в грань» в базовой модели разваливается в семействах
  стилей: lowpoly сужает коробки, toy/clean/realistic снимают фаски с рёбер, realistic утапливает панели, lofi сдвигает всё на
  сетку 2 см, derelict гнёт и мнёт. `meshfix` притягивает куски до 7 см, но зазор — ошибка модели, а не повод для починки.
- **Стоящее на полу не двигается.** Ступня, колесо, гусеница: если они отстают, к ним опускается корпус (`meshfix`), иначе робот
  ходил бы по воздуху. Ногу тяни до самого ботинка (`limb` до z ≈ 0.04, а не 0.1).
- **В lofi ничего тоньше клетки сетки (2 см)** — тоньше схлопнется в ноль; `style_families` утолщает коробки и цилиндры, но
  в `guards.py`/`players.py` (`limb` 7 мм) следи сам.
- **Люди не похожи на роботов.** Шары в плечах, коленях и кистях делают персонажа манекеном: людям — рукава, варежки, ботинки;
  шарниры — роботам.
- **Детали перекрываются объёмом, а не гранью.** Два торца в одной плоскости (дно шеи и дно воротника, верх ремня и верх таза,
  рамка решётки в углах, наконечник вплотную к торцу) — z-fighting. Сдвинь одну деталь на 2–5 мм внутрь другой.
- Сегменты: крупные лофты 28–32, конечности 16–20, суставы 12–16, мелочь 8–12. Шар — дорогой: на мелочь — `seg=12`.
- **Любая стенка, ступень, шов, прорезь — шире двух фасок**, иначе фаска «зажимается» по всему объекту (scenario-labs, проверено в 5.2.1).
- Круглый вырез в круглой детали — со сдвигом на полсегмента (`rot` на `π/seg`), иначе полосы и non-manifold рёбра.
- Пересечение двух деталей «в лоб» выглядит фальшиво — прикрыть воротником, муфтой, фаской (сустав, `collar`).
- **Бюджет**: мебель 0,3–3 тыс. треугольников, мелкий предмет < 1 тыс., робот/игрок 6–10 тыс. (главный враг — до 13 тыс.:
  `guard_mk2` 12,5 тыс., Derelict-охранник 10,4 тыс.). Смотри `CHECK … tris`.
- **Контракт частей сильнее совета критика.** Всё, что едет с ногой, живёт в `AccentLeg*` и красится акцентом; бедро 0,9 м и колено
  0,45 м зафиксированы игрой. Совет «серые щитки на ноги» или «укоротить ноги» без смены контракта не выполнить — скажи это прямо.

## Подводные камни (Blender 5.2)

- `bisect_plane` ровно через кольцо вершин (шар/цилиндр по центру колена) даёт вырожденные грани и дыры — `split_at` сдвигает плоскость на 0,7 мм.
- Skin: слой `skin_vertices` появляется только **после** добавления модификатора — сначала модификатор, потом радиусы.
- Кривые (`tube`): крышки приходят несваренными — `_evaluated` делает `remove_doubles`.
- Auto Smooth в 4.1+ удалён: острые рёбра — флаг `edge.smooth = False`, складки subsurf — атрибут `crease_edge`.
- Boolean: `solver = "EXACT"`; после выреза — `bevel_edges`, иначе край как от ножа.
- FBX: `axis_forward="-Z", axis_up="Y", bake_space_transform=True`, `use_mesh_modifiers=True` (Weighted Normal применится,
  нормали едут в Unity — импорт нормалей по умолчанию Import).
- `style_families.py` подменяет только `generate_models.box/cylinder/sphere`; модели на `shapes.py` семейства стилей **не перестраивают**:
  для них свои варианты по стилям — как охранники в `guards.py`.
- Скрипты моделей пишут FBX прямо в `Assets/…` — экспериментируй в scratchpad, в ассеты — когда модель принята.
- `bmesh.ops.bevel` по умолчанию `segments=0, profile=0.0` — всегда передавать оба.
- Нормали после модификаторов читать из `mesh.corner_normals` (split normals старого API нет).
- Рендер: EEVEE — `BLENDER_EEVEE` (`…_NEXT` падает); по умолчанию AgX — для сверки цветов ставить `Standard` (review.py ставит).
- Скульпт-кисти без окна не работают: `sculpt.brush_stroke` не проходит poll, а `sculpt.mesh_filter`, `paint.mask_flood_fill`,
  `sculpt.symmetrize`, `voxel_remesh` в режиме скульпта **роняют Blender**. Органику — через `skin`/`smooth`/лофты или SDF
  (smooth-min + `openvdb`, как `Clay` в scenario-labs `bx_sculpt.py`); живые кисти — только в открытом Blender
  (UnityMCP `blender_bridge`).
- Unity отбрасывает задние грани: деталь с вывернутыми нормалями в игре станет дырой. `part()` пересчитывает нормали, но для
  чужих мешей проверяй рендером с отсечением задних граней.

## Что даёт прогон (ноябрь 2026, все 679 моделей стилей)

Было около 400 моделей с ошибками ворот, после `meshfix` и правок базовых моделей — 10 (совпадающие грани внутри одного куска
и пара зазоров меньше сантиметра). Источники ошибок по убыванию: детали «на глаз» в базовых заготовках (папки над полкой,
перекладины дрона мимо винтов), семейства стилей (сужение, фаски, сетка, вмятины), совпадающие грани. Критик по линейкам:
охранники 3–8 из 10, игроки 2–5: стили различаются в основном головой; следующий шаг — свой язык ног у каждого охранника
и силуэт стиля в крупных формах (детали мельче 3 см с 15 м не видны).

## Шаблон для критика (субагент, без кода)

> You are a senior game 3D artist. You get only renders, on purpose — judge what you see. Context: <что это, где в игре,
> с какого расстояния видно, бюджет, что значат цвета>. Image: <путь>; layout: <строки/столбцы листа, где старая, где новая>.
> Answer: 1) verdict new vs old, 2) silhouette at 64 px, 3) proportions and form language (locations precisely),
> 4) visible defects, 5) top 6 changes ranked by impact, prefer big forms over greebles. Under 450 words.

## Готовый набор scenario-labs (MIT)

[scenario-labs/skills](https://github.com/scenario-labs/skills) → `skills/dcc/blender`: 15 скиллов-экспертов Blender, проверены
без окна в Blender 5.2.1 (нашей версии). Полезное нам, чего нет в `shapes.py`/`review.py`:
- `bx_audit.deliverable(objs, profile="game")` — ворота перед экспортом: висящие и спрятанные внутрь детали, **z-fighting**
  между частями, вывернутые детали, грани внутрь, масштаб, нет UV.
- `bx_review` — режимы matcap / silhouette / normals / wire, `culling=True` (грани внутрь — пурпурные дыры, как в Unity),
  ракурс снизу; в `bx_hardsurface.review` — блестящий матcap и «полосы отражения» (полоса рвётся на фаске — смаз нормалей).
- `bx_hardsurface`: стек «дизайн-фаска по весам → вырезы → микрофаска 30° с Harden Normals → Weighted Normal»,
  `shading_audit` (смаз: нормаль угла отклонена > 3° от плоской грани; сглаженные острые рёбра; неплоские грани), чистые вырезы.
- `critique.md` в каждом скилле — рубрика «что смотрит эксперт → какой код это проверяет → порог». Вердикт кода и глаз должны
  совпасть: чистый вердикт при плохом крупном плане = дефект, которого код не меряет.

## Потенциальные улучшения (не сделано, решили отложить)

**Живой Blender через MCP** (решено 2026-11-11: записать, пока не ставить). Сейчас его нет: в Blender 5.2 нет аддона,
у Claude подключён только UnityMCP. Что даст:
- настоящий скульпт кистями — без окна кисти не работают, органика упирается в качество эскиза;
- `blender_bridge` в UnityMCP (тот же аддон, сокет 127.0.0.1:9876): импорт модели в открытую сцену Unity и `compare_screenshot`
  «Blender | Unity» — видно модель с настоящими материалами и стилем игры;
- быстрые мелкие правки в открытой сцене без пересборки скрипта.

Как поставить: аддон `mcp-for-blender` (бывший `blender-mcp`, [ahujasid/blender-mcp](https://github.com/ahujasid/blender-mcp))
в Blender 5.2 (`uvx mcp-for-blender install-addon` или `addon.py` через Preferences → Add-ons) + MCP-сервер `uvx mcp-for-blender`
только для этого проекта на своей машине, не в репозиторий. Обязательно `DISABLE_TELEMETRY=true` (минимальная телеметрия включена
по умолчанию). Порт без пароля исполняет любой Python — только localhost. Окно Blender открывает человек, не агент (фокус).
Совместимость с Blender 5 не заявлена — после установки проверить на простой сцене. Основной путь остаётся скриптовым:
воспроизводимый код + `review.py`.

сравнение работают, CLIP-похожесть — нет).
